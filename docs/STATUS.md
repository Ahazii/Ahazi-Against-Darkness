# Current Status

Last updated: 2026-07-12

## Summary

- **Abyss group-treasure and expert-choice correction (2026-07-12):** Abyss encounter treasure rows now apply once to each generated foe group, not once to every member of that group. This fixes Final Boss treasure inflation such as Chaotic Ratmen producing dozens of rolls before the printed Final Boss triple is applied. The XP panel now hides ineligible Expert skills/spells; the existing server validation remains the authoritative protection against invalid class, level, training, or duplicate choices. EE p.105 defines Final Boss treasure as triple gp or 100gp minimum, and Abyss p.52 gives Chaotic Ratmen two group treasure rolls.
- **Treasure staging integrity (2026-07-12):** Secret-door treasure doubles are now explicitly applied once and persist an application marker on the tile. Legacy saves whose recorded summary already says `doubled behind secret door` are recognised without applying a second multiplier. Treasure-roll merging now shares the same reusable award module as Abyss group-roll and Final Boss guards. This preserves the printed one-time secret-door doubling rule while preventing repeated staging from inflating gold.
- **Locked declared source snapshots (2026-07-11):** New sessions now persist the manifest-declared packaged files for their active runtime supplements. Copy Narrative Report shows them in Registry Context, while saved-session lists remain compact and only expose supplement identity/version context. Imported review packages remain excluded until a validated promotion creates executable content; this is provenance metadata only.
- **Manifest-driven class and item ownership (2026-07-11):** Character-class and item catalogues now use the manifest `content_sources` inventory for provider discovery. Existing `class_source_books` still assigns the Courtship entries inside the shared class file, and items retain their direct-shop versus named table-backed distinction. Existing character and item engines remain authoritative; this is ownership metadata migration only.
- **Manifest-driven foe ownership (2026-07-11):** The foe catalogue and runtime Workbench now discover packaged foe data from manifest `content_sources`. The special Abyss source is constrained to its explicit encounter foe tables, so a declared shared table file does not turn room/procedure rows into false foe records. Existing encounter selection and combat execution remain unchanged.
- **Manifest-driven rule-table ownership (2026-07-11):** The table catalogue now discovers packaged provider files from the manifest `content_sources` inventory, retaining the former map only when no packaged manifest is available. Derived app-owned table records remain explicit. Live table merging and all rule outcomes still use the existing `RulesRepository` path; this is a catalogue-ownership migration only.
- **Manifest-driven random-tile ownership (2026-07-11):** The room-tile catalogue now reads built-in manifest `content_sources` when a packaged registry is available, with the former provider map retained only as a source-free fallback. The runtime Workbench uses that resolved catalogue too. EE and Forsaken Depths tile data, dice keys, and map placement behavior are unchanged; this moves ownership discovery toward the manifest boundary without making imported tiles executable.
- **Manifest-declared packaged content sources (2026-07-11):** Built-in supplement manifests now list their structured data sources by content family. The runtime Workbench displays this read-only inventory beneath each supplement, so ownership no longer lives only in catalogue code: it distinguishes direct bestiaries/shop files from table-backed Abyss rewards and identifies the separate FD dungeon/river tile files. These declarations are audit metadata only and do not change loaders or gameplay.
