# Four Against Darkness - Adventure Engine

This project is a FastAPI-based web app that runs random adventures and is
structured to accept imported adventure data in a later phase. The current
build focuses on:

- Character creation and storage
- Party selection
- Random dungeon generation
- Map rendering with current room/enemy display
- Player-facing combat resolution

## Docker Development

Run the dev stack with hot reload:

```
docker compose -f docker-compose.dev.yml up --build
```

Then open `http://127.0.0.1:8000`.

## Docker Image (GHCR)

Images are built and published to GitHub Container Registry via GitHub Actions.
The workflow publishes:

- `ghcr.io/ahazii/ahazi-against-darkness:0.1.0`
- `ghcr.io/ahazii/ahazi-against-darkness:latest`
- `ghcr.io/ahazii/ahazi-against-darkness:sha-<commit>`

After pushing to `main`, wait for the workflow to complete, then pull:

```
docker pull ghcr.io/ahazii/ahazi-against-darkness:0.1.0
```

## Environment Variables

All configuration is environment-driven.

- `APP_HOST` (default: `0.0.0.0`) - FastAPI host binding
- `APP_PORT` (default: `8000`) - FastAPI port
- `DATA_DIR` (default: `.data`) - persistent data path for saved characters,
  parties, sessions, and tables (stored under `DATA_DIR/tables`)
- `PUID` (optional) - run the app as this user id (Unraid default: 99)
- `PGID` (optional) - run the app as this group id (Unraid default: 100)

## Build Arguments

The Docker image supports these build arguments:

- `APP_USER` (default: `appuser`) - non-root runtime user
- `APP_UID` (default: `10001`) - UID for the runtime user

## Data Persistence

State is stored in `DATA_DIR` and is expected to be backed by a named volume
in Docker. The development compose file mounts:

- `4ad_data:/data`

## Unraid Template

An Unraid template is included at `my-ahazi-against-darkness.xml`.

## Adventure Architecture

- Random adventures are generated by the `RandomAdventure` module.
- Imported adventures will be added by implementing `list_imported_adventures`
  and by adding adventure definitions to the `DATA_DIR` when ready.

## Notes

This implementation is structured for future expansion:

- Enemies and classes are driven by JSON data files.
- The map and combat systems are separated from storage and UI layers.
